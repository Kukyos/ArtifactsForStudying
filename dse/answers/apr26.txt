=== Apr26 Q20b
<p>K-means is an <b>unsupervised, partition-based</b> clustering algorithm that groups unlabelled data into a chosen number K of clusters by minimising the distance between each point and the centre (centroid) of its cluster. Euclidean distance is used.</p>
<h4>Algorithm</h4>
<ol class="steps">
<li>Decide the number of clusters K (for example with the elbow method).</li>
<li>Choose K initial centroids (random points or chosen seeds).</li>
<li>Calculate the distance of every data point to each centroid.</li>
<li>Assign every point to its nearest centroid.</li>
<li>Recompute each centroid as the mean of the points in its cluster.</li>
<li>Repeat steps 3 to 5 until the centroids stop moving (no point changes cluster).</li>
</ol>
<img class="fig" src="img/kmeans_flow.png" alt="flow chart of the K-means algorithm">
<p><b>Advantages:</b> simple, fast (time O(n k t)), every point goes to exactly one cluster. <b>Limitations:</b> K must be chosen beforehand, result depends on the starting centroids (local optimum), sensitive to outliers, not suitable for non-convex clusters.</p>

=== Apr26 Q21b
<p><b>Entropy</b> measures the impurity (uncertainty, disorder) of a set of examples:</p>
```gbox
Entropy(S) = - sum p_i log2 (p_i)
```
<ul><li>Entropy = 0: all examples belong to one class (pure, no uncertainty).</li><li>Entropy = 1: two classes equally mixed (maximum uncertainty).</li></ul>
<p><b>Information gain</b> is the reduction in entropy obtained by splitting on an attribute A; ID3 splits on the attribute with the highest gain:</p>
```gbox
Gain(S, A) = Entropy(S) - sum over values v of A of  (|Sv| / |S|) x Entropy(Sv)
```
<p><b>Example</b> (the speed data of Q21a): parent has 2 Slow and 2 Fast, so Entropy = -(1/2)log2(1/2) - (1/2)log2(1/2) = 1. Splitting on Speed limit gives two pure groups (entropy 0 each), weighted entropy = (2/4)(0) + (2/4)(0) = 0, so Gain = 1 - 0 = <b>1</b>. Splitting on Obstruction leaves both groups half-and-half (entropy 1), so Gain = 1 - 1 = <b>0</b>: it tells nothing about the speed.</p>

=== Apr26 Q23a
<p><b>Online bookstore: a hybrid recommender.</b></p>
<ol class="steps">
<li><b>Data:</b> books (title, author, genre, keywords, price), users (age, past purchases, browsing, wish-list) and ratings and reviews. Explicit data is ratings; implicit data is purchases, clicks and time spent.</li>
<li><b>Content-based part:</b> describe each book as a vector (genre, author, keywords by TF-IDF); build a user profile from the books the user bought or liked; recommend the books with the highest cosine similarity to the profile. This also serves new books and new users with a few purchases.</li>
<li><b>Collaborative part:</b> build the user-book utility matrix; find users with similar rating patterns (cosine or Pearson similarity); recommend the books they liked that this user has not read (or item-based: "customers who bought this also bought").</li>
<li><b>Hybrid:</b> score = a x CF + (1 - a) x CBF, or switch: content-based for a new customer, collaborative once enough ratings exist.</li>
<li><b>Output:</b> a ranked top-N list on the home page and the product page, excluding books already bought.</li>
<li><b>Evaluation:</b> MAE and RMSE of predicted ratings, hit rate and ARHR for the top-N list, plus coverage, diversity and novelty; run A/B tests on conversion.</li>
<li><b>Problems to handle:</b> cold start, sparse data, popularity bias, and privacy of purchase history.</li>
</ol>
