=== Nxt25 Q9
<p><b>Synchronous</b>: each operation (create, read, update, delete) blocks; the next line waits until it finishes, e.g. <code>fs.readFileSync()</code>. Simple to write, but freezes the page or server while waiting. <b>Asynchronous</b>: the operation starts and the code continues; the result arrives later through a callback, a Promise or <code>async/await</code>, e.g. <code>fetch()</code> or <code>await Student.find()</code>. Used for databases and servers because the app stays responsive while it waits.</p>

<p>A media query on <code>orientation</code> changes the colours when the device is turned. In the preview, make the frame wider or narrower than it is tall, or rotate a phone.</p>
```run html

    }

    @media (orientation: landscape) {
      body { background-color: #fde68a; color: #7c2d12; }

  <p class="mode"></p>
</body>
</html>
```
<p><code>orientation: portrait</code> applies when height ≥ width and <code>landscape</code> when width &gt; height. The viewport meta tag makes the page use the device width. === Nxt25 Q14
<p>The two ways to define a function:</p>
<ul>
<li><b>Function declaration</b> (named function): <code>function add(a, b) { return a + b; }</code>. It is <b>hoisted</b>, so it can be called before the line where it is written.</li>
<li><b>Function expression / arrow function</b>: the function is stored in a variable: <code>const mul = function (a, b) { return a * b; };</code> or <code>const mul = (a, b) =&gt; a * b;</code>. It is <b>not hoisted</b>, so it can only be called after it is defined; arrow functions are shorter and are commonly used as callbacks.</li>
</ul>
```js
console.log(add(2, 3));          // 5: works, declarations are hoisted

function add(a, b) {
  return a + b;
}

const mul = (a, b) => a * b;     // arrow function expression
console.log(mul(4, 5));          // 20

[1, 2, 3].forEach(n => console.log(n * 10));   // arrow function as a callback
```
<p>(If the question means <b>built-in vs user-defined</b> functions: built-in ones come with JavaScript, like <code>alert()</code>, <code>parseInt()</code> and <code>Math.max()</code>; user-defined ones are written by the programmer, like <code>add()</code> above.)</p>

=== Nxt25 Q23
<p>A form's <code>method</code> attribute decides how its data is sent to the <code>action</code> URL:</p>
<table class="tbl"><tr><th>GET</th><th>POST</th></tr>
<tr><td>Data is added to the <b>URL</b> as a query string: <code>/search?q=html&amp;page=2</code></td><td>Data goes in the <b>request body</b>, not visible in the URL</td></tr>
<tr><td>Limited length; can be bookmarked and cached</td><td>No practical size limit; can carry files</td></tr>
<tr><td>For fetching data: searches, filters</td><td>For sending or changing data: login, registration, payments</td></tr>
<tr><td>Not for passwords (they appear in the URL and history)</td><td>Safer for sensitive data (still needs HTTPS)</td></tr></table>
```run html

  <input type="submit" value="Search">
</form>

<h4>POST: login</h4>
<form action="/login" method="post">
  Username: <input type="text" name="username"><br>
  Password: <input type="password" name="password"><br>
  <input type="submit" value="Login">
</form>
```
<p>Submitting the GET form opens <code>google.com/search?q=your+words</code>: the data is in the URL. A POST form sends <code>username=…&amp;password=…</code> in the body; on the server, Express reads it with <code>express.urlencoded()</code> into <code>req.body</code>, and GET data from <code>req.query</code>.</p>

```run html
    function addRuns(r) {
      runs += r;
      balls++;
      if (r == 4) fours++;
      if (r == 6) sixes++;
      document.getElementById("last").innerHTML = "Last ball: " + (r == 1 ? "Single" : r == 4 ? "FOUR!" : "SIX!");

    function show() {
      document.getElementById("score").innerHTML = runs + "/" + wickets;
      document.getElementById("balls").innerHTML = balls;
      document.getElementById("overs").innerHTML = Math.floor(balls / 6) + "." + (balls % 6);
      document.getElementById("fours").innerHTML = fours;
      document.getElementById("sixes").innerHTML = sixes;
    }

    function reset() {
      runs = wickets = balls = fours = sixes = 0;
      document.getElementById("last").innerHTML = "";
      show();
    }
  </script>
</body>
</html>
```
<ul><li>The score is kept in JavaScript variables; each button calls <code>addRuns()</code> with 1, 4 or 6.</li>
<li><code>show()</code> rewrites the scoreboard with <code>innerHTML</code> after every click, so the "live score" updates instantly without reloading.</li>
<li>Overs are balls ÷ 6 written as overs.balls (e.g. 8 balls = 1.2 overs).</li></ul>
