=== Nov25 Q18b
<p>The <code>position</code> property decides how an element is placed. The default is <code>static</code> (normal flow).</p>
<ul>
<li><b>Relative</b>: the element stays in the normal flow (its space is kept), but is shifted from <b>where it would normally be</b> by top/left/right/bottom.</li>
<li><b>Absolute</b>: the element is taken <b>out</b> of the normal flow (other elements close the gap) and placed relative to its <b>nearest positioned ancestor</b> (one with position other than static), or the page if there is none.</li>
</ul>
<p>Applied to the timetable: the table is made <code>relative</code> and moved 20px right and 10px down; a "NEW" badge is placed with <code>absolute</code> at the table's top-right corner. Because the table is positioned, the badge is measured from the table, not from the page.</p>
```run html
<!DOCTYPE html>
<html>
<head>
  <style>
    table, th, td { border: 1px solid black; border-collapse: collapse; }
    th, td { padding: 8px 14px; text-align: center; }

    /* (i) relative: moved from its normal place, space still reserved */
    .timetable {
      position: relative;
      top: 10px;
      left: 20px;
    }

    /* (ii) absolute: placed inside the nearest positioned ancestor (the table) */
    .badge {
      position: absolute;
      top: -12px;
      right: -12px;
      background: red;
      color: white;
      padding: 3px 8px;
      border-radius: 10px;
      font-size: 12px;
    }
  </style>
</head>
<body>
  <table class="timetable">
    <tr><th colspan="2">Seminar Timetable <span class="badge">NEW</span></th></tr>
    <tr><th>Day 1</th><th>Day 2</th></tr>
    <tr><td colspan="2">Welcome Address</td></tr>
    <tr><td>Web Technologies</td><td>Cloud Computing</td></tr>
    <tr><td>Artificial Intelligence</td><td>Cyber Security</td></tr>
  </table>
</body>
</html>
```
<table class="tbl"><tr><th></th><th>Relative</th><th>Absolute</th></tr>
<tr><td>In normal flow?</td><td>Yes, its space is kept</td><td>No, removed from flow</td></tr>
<tr><td>Offsets measured from</td><td>its own normal position</td><td>nearest positioned ancestor</td></tr>
<tr><td>Typical use</td><td>small nudges; acting as the container for absolute children</td><td>badges, tooltips, overlays</td></tr></table>

    function convert() {
      var g = document.getElementById("grams").value.trim();
      var out = document.getElementById("result");

        out.innerHTML = "Please enter a valid number.";
        return;
      }
      if (Number(g) < 0) {
        out.className = "error";
        out.innerHTML = "Weight cannot be negative.";
        return;

      var kg = Number(g) / 1000;
      out.className = "";
      out.innerHTML = g + " g = " + kg + " kg";

      document.getElementById("result").innerHTML = "";
    }
  </script>

// 1. object
let smartDevice = {
  deviceName: "Smartwatch X100",
  deviceId: 102,
  category: "Wearables",
  specs: ["Heart Rate Monitor", "GPS", "Water Resistant"],
  available: false,
  price: 14999.99
};

// 2. serialization: object -> JSON string
let jsonStr = JSON.stringify(smartDevice);

console.log("Deserialized object:");

// 4. read values from the object

} else {

}

<p>Express handles the routes; <b>Mongoose</b> connects to MongoDB and defines the Student model. Setup: <code>npm init -y</code>, then <code>npm install express mongoose</code>, start MongoDB, run <code>node server.js</code>.</p>
```js
// server.js
const express = require("express");
const mongoose = require("mongoose");

const app = express();
app.use(express.json());          // read JSON request bodies

// connect to MongoDB
mongoose.connect("mongodb://127.0.0.1:27017/universityDB")
  .then(() => console.log("Connected to MongoDB"))
  .catch((err) => console.log("DB connection error:", err.message));

// schema and model
const studentSchema = new mongoose.Schema({
  name: { type: String, required: true, unique: true, trim: true },
  department: { type: String, required: true },
  cgpa: { type: Number, required: true, min: 0, max: 10 }
});
const Student = mongoose.model("Student", studentSchema);

// POST /api/addStudent : add a new student
app.post("/api/addStudent", async (req, res) => {
  try {
    const { name, department, cgpa } = req.body;
    if (!name || !department || cgpa === undefined) {
      return res.status(400).json({ message: "name, department and cgpa are required" });
    }
    const existing = await Student.findOne({ name: name.trim() });
    if (existing) {
      return res.status(409).json({ message: "Student with this name already exists" });
    }
    const student = new Student({ name, department, cgpa });
    await student.save();
    res.status(201).json({ message: "Student added successfully", student });
  } catch (err) {
    if (err.code === 11000) {               // unique index caught a duplicate
      return res.status(409).json({ message: "Student with this name already exists" });
    }
    if (err.name === "ValidationError") {   // schema rule broken, e.g. cgpa > 10
      return res.status(400).json({ message: err.message });
    }
    res.status(500).json({ message: "Error adding student", error: err.message });
  }
});

// GET /api/viewAllStudents : fetch all students
app.get("/api/viewAllStudents", async (req, res) => {
  try {
    const students = await Student.find();
    res.status(200).json(students);
  } catch (err) {
    res.status(500).json({ message: "Error fetching students", error: err.message });
  }
});

app.listen(3000, () => console.log("Server running on http://localhost:3000"));
```

<li><b>Duplicate check</b>: before saving, <code>findOne({ name })</code> looks for the same name and returns <b>409 Conflict</b> with a message. <code>unique: true</code> in the schema is a second guard at the database level: if two requests race past the check, MongoDB rejects the second with error code 11000, which the catch also turns into 409.</li>
<li><b>Validation</b>: missing fields give <b>400 Bad Request</b>; the schema enforces types and 0 ≤ CGPA ≤ 10, and a broken rule (a <code>ValidationError</code>) is also returned as 400, as the CGPA 12 request shows.</li>
<li><b>Error handling</b>: each route is wrapped in <code>try/catch</code>; anything else (e.g. the database is down) returns <b>500</b> with the error message.</li>
<li>Status codes: 201 Created for a new student, 200 OK for the list.</li>
